# Isaac-Link 0.7.0 implementation and acceptance

Status: v0.7.0 published on GitHub Release. **Live Steam and two-ended public NAT acceptance remains pending**; updater verification is separate from multiplayer acceptance.

## Architecture

The native `desktop` entry point uses PySide6 Widgets. `backend` holds the extracted legacy application controller; `desktop_backend` provides the new command/snapshot boundary. Legacy browser entry points and tests remain available for comparison. Runtime7 attaches the 32-bit game through hook7; the Windows application itself is x64.

Session7 owns room identity, host-authored configuration revisions and per-pair selectors. Steam is the bootstrap carrier; no coordinator registration is needed to create a room. Invitations require explicit recipient acceptance. Transient carrier failures never elect a new host or change room keys. Game-process exit is not a recoverable network outage: users reconnect the game explicitly.

Transport7 retains the existing reliable framing, sequence space, reassembly, authentication and four-input redundancy. The Steam carrier uses the same game envelope as UDP. Normal switching preserves reliable queues and allows 500 ms of duplicate transmission; existing deduplication prevents duplicate game delivery. Control and game routes have independent policies.

Control messages are AES-GCM encrypted with per-pair room keys, in addition to the outer authentication, because room snapshots carry member bootstrap tokens. Room identity and direction are bound as associated data. Steam bootstrap invitations use the recipient's invitation secret and the Steam-reported sender identity. Control/bootstrap packets fit within Steam's 1200-byte unreliable limit.

Steam session requests use a retained 32-bit CCallbackBase for callback 1202. Bootstrap packets are accepted only after verifying the recipient's connection-code token and Steam-reported sender identity. This callback ABI and the original game's handling of simultaneous Steam callbacks **need validation in the actual game**; simulated Python carriers and JS lifecycle fixtures cannot prove that ABI works on a user's game build.

## Default policies

- Game route: automatic per pair, first usable route followed by evaluation every 30 s, with a 5 s / 10 Hz sample window. Score is worse-direction RTT P95 + 1000 × loss fraction. At least three replies per direction and at most 25% loss are required for a ranked candidate.
- Optimization requires >=10 points and >=20% improvement in two different rounds, with a 60 s cooldown. Failure after 3 s bypasses optimization hysteresis; fallback still needs bidirectional evidence and switch confirmation.
- Control: one host-selected route for the entire room, default Steam. Optional server, configured LAN and validated IPv6/IPv4 can be selected in Settings. No per-pair fallback; all-game-auto does not change this setting.
- The smaller SteamID coordinates each pair's prepare/ready/commit/done handshake. Versioned messages are acknowledged, deduplicated and retried. Host absence does not block an already configured pair's automatic operation.
- Public STUN: Cloudflare UDP 3478 and Google UDP 19302; the Discovery class accepts a configurable server list. Same application UDP socket for discovery and game data. Custom server discovery is retained when configured. Candidate addresses never count as successful direct paths without challenge verification.
- Discovery losses before a peer installs its session keys are discarded when a path first establishes or recovers. They are not counted as steady-state route loss.

## Update and packaging

The x64 portable directory contains the application, replaceable Qt libraries and a separately frozen updater. GitHub `releases/latest/download/update.json` is the initial source. No Gitee mirror is active. A signed manifest can carry multiple HTTPS package URLs when a mirror is deployed.

Ed25519 authenticates exact manifest and package bytes. The client embeds only `release_public_key.txt`. The initial publisher key is stored in `%LOCALAPPDATA%/IsaacLinkPublisher/release-ed25519.pem`, outside the checkout. Back up that file privately before changing machines. Future official packages must use the same publisher key unless a deliberate trust-key migration is implemented.

Automatic checking is optional. Installation is only offered after disconnecting the helper. The updater validates signed metadata, rejects wrong protocol/platform, same-version/downgrade packages and unsafe ZIP paths, stages on the installation volume, waits for the old process, renames the previous directory, and waits for a ready marker from the new UI. Startup failure restores the old directory. Logs/captures are copied forward; profile data remains under LOCALAPPDATA. Previous/failed directories are retained for inspection; no recursive cleanup is performed automatically.

0.6.5 cannot self-update to 0.7.0: download/extract this version manually first. Protocol 8 clients do not accept old connection codes. Optional servers use `/v7/register` and `/v7/alive`, plus authenticated UDP discovery/forwarding. An incompatible server is marked unavailable, without disabling Steam-based rooms.

Build:

```powershell
.\.venv\Scripts\python.exe -m pip install -r scripts/requirements-build.txt
# First publisher setup only; private key is never placed inside the repository.
.\.venv\Scripts\python.exe scripts/release7.py --init-key
.\.venv\Scripts\python.exe -m PyInstaller --noconfirm scripts/Updater.spec
.\.venv\Scripts\python.exe -m PyInstaller --noconfirm scripts/Isaac-Link.spec
.\.venv\Scripts\python.exe scripts/release7.py
```

`scripts/publish_release.py --publish` uploads all assets into a draft before publishing it as the latest release. Use `--direct-upload` when the configured proxy cannot upload large assets. The command refuses to overwrite a published release.

For the next release: increment `isaac_link/version.py`, add matching `docs/releases/<version>.md`, build both executables, run `release7.py` using the existing publisher key, commit/push, then publish. Client update discovery requires a higher semantic version and a compatible protocol/platform. Merely pushing Git commits does not publish an update. Keep the publisher private key backed up outside the repository; replacing it would break signature verification in already-installed clients.

## Verification and remaining live acceptance

Reproducible checks:

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -p "test_*.py"
node tests/test_carrier_shutdown.cjs
node tests/test_hook7.cjs
# Optional verification dependencies only:
.\.venv\Scripts\python.exe -m pip install playwright psutil
.\.venv\Scripts\python.exe scripts/validate_desktop7.py
```

Tests cover legacy behavior, selectors, strict locks, four-member server-free rooms with a simulated Steam carrier, dropped switch confirmation, real loopback UDP after simulated Steam/host failure, STUN transaction/source validation, relay isolation, signed-package rejection, interrupted/truncated downloads, startup failure rollback and preservation of user captures. These tests do not claim public NAT or Steam success.

Native screenshots are saved under `ui-validation`, covering four themes and 100/150/200% rendering. Headless Edge versus offscreen Qt measurements are synthetic and include process-family startup. The offscreen Qt worker explicitly loads Windows fonts; otherwise it would render missing-glyph boxes and underestimate useful rendering work. CPU/RAM data and timer intervals are stored as JSON. They are not in-game performance measurements.

Live acceptance before stable release:

1. Two actual Steam accounts, then four: invitation before official-room entry, mutual visibility, game input, callbacks and clean shutdown.
2. Compare public STUN and custom-server discovery on the same pair of real networks, alternating runs. Record direct-path success and time separately from Steam/relay fallback.
3. Interrupt Steam, the optional server, LAN and direct UDP separately; confirm strict locks, no host election, retry recovery and stale telemetry labels.
4. Induce latency improvement and small alternating differences; confirm the 30-second sampling and anti-flapping policy in actual game traffic.
5. Publish a private/test signed version on an HTTPS source, verify real download and frozen-updater restart on another Windows machine. No such published upgrade has been tested in this run.

Known physical limit: if all usable communication paths disappear, there is no channel to communicate a new NAT endpoint until a carrier recovers. The helper cannot restore an official game room that the game itself has already closed.
